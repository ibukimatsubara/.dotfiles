# Blueprint: Kensington 4ボタンのマウス完結操作

状態: 実装済み（2026-11-15）。4ボタンの対応は実機のログで確認済み。

## 目的と前提

キーボードに手を伸ばさず、Kensingtonの4ボタンでクリック、ウィンドウのフォーカス移動、作業スペース切り替え、音声入力を操作する。

- 利用者がキーボードの修飾キーを押す操作は使わない。
- 単押しだけでなく、上下・左右・対角のボタン同時押しを使ってよい。
- 左右クリック、ドラッグ、通常のスクロールは維持する。
- 先に「機能とマウス操作」の対応を決め、実装方式は実機の入力を確認してから選ぶ。
- 以下の割り当ては提案であり、個別の組み合わせへの最終合意はまだ取っていない。

## ボタンの呼び方

```text
［左上］       ［右上］
        ボール
［左下］       ［右下］
```

実機の既定割り当ては、下段が左右クリック、左上がmiddleクリック、右上がsideボタンだった。

## 操作一覧

「＋」はマウスの2ボタン同時押し。表中のキー名はソフトウェア側が生成する入力であり、利用者がキーボードを押す必要はない。

| マウスの操作 | 機能 | 入力・動作 |
| --- | --- | --- |
| 左下 | 左クリック | 通常の選択。押したままボールを動かすとドラッグ |
| 右下 | 右クリック | コンテキストメニューを開く |
| 左上 | 左のウィンドウへフォーカス | 同じワークスペース内で操作対象を左へ移す |
| 右上 | 右のウィンドウへフォーカス | 同じワークスペース内で操作対象を右へ移す |
| 左上＋左下 | 前のワークスペースへ | 作業スペースを前へ切り替える |
| 右上＋右下 | 次のワークスペースへ | 作業スペースを次へ切り替える |
| 左上＋右上 | 音声入力の開始／停止 | 音声入力のトグル操作を呼び出す |
| 左下＋右下 | 中クリック | アプリの中クリック動作。例: リンクを別タブで開く |
| 左上＋右下 | 確定 | Enter相当。アプリによって改行・確定・送信など動作が異なる |
| 右上＋左下 | キャンセル | Esc相当。音声入力の破棄にも使うかは別途確認 |

覚え方は「上の単押しでフォーカス」「左右それぞれの上下同時押しでワークスペース」「上2つで音声入力」。

4通りの単押しと6通りの2ボタン同時押しを使う。3ボタン同時押しの4通りと、4ボタン同時押しの1通りは未割り当てで残す。長押しや専用のダブル押しによる追加機能は、今回の案には含めない。通常のダブルクリックは維持する。

## 実装前に確認すること

1. **機種と入力イベント**: 接続中のKensingtonの型番、4ボタンのコード、スクロール方式、各同時押しがOSへ届くかを確認する。→ 型番・コード・位置の対応まで確認済み。
2. **切り替え対象**: 会話中の「ウィンドウセッションの左右」は、この案ではHyprlandのワークスペースと仮定している。tmuxのウィンドウ／セッションを指す場合は対象を変更する。
3. **ワークスペースの前後**: 空の番号も含めるか、使用中だけを巡回するか、端で折り返すかを決める。
4. **音声入力の呼び出し先**: 会話ではCtrl＋Space相当としていたが、リポジトリの[音声入力資料](../voxtype.md)はShift＋SpaceからTalk Switchを呼ぶ構成を記載している。現在の実機で有効な切り替え先を確認し、キー入力の生成か直接のコマンド呼び出しかを選ぶ。
5. **同時押しの判定**: 押す順番やわずかな時間差を許容する範囲、単押しを確定するタイミング、押しっぱなし時の挙動を決める。通常クリック・ドラッグの応答性との両立を実機で確認する。
6. **既存設定との競合**: 既存のマウス設定やデバイス側の同時押し機能との二重発火を避ける。設定は対象のKensingtonに限定する。

## 動作確認の条件

- キーボードに触れず、操作一覧の全10通りを実行できる。
- 左右クリック、ダブルクリック、ドラッグ、スクロールが従来どおり使える。
- 同時押しでは割り当てた機能だけが1回発火し、構成する各ボタンの単押しは発火しない。
- 同時押しの押す順番・離す順番が違っても、余分なクリックやキー入力が発生しない。
- 2ボタンを押したままにしても、音声入力のトグルやEnterが意図せず繰り返されない。
- 未割り当ての3ボタン・4ボタン同時押しで、意図しない操作や押しっぱなし状態が残らない。
- フォーカス移動とワークスペース切り替えが混同されず、決めた対象へ移動する。
- 音声入力は開始・停止の両方ができ、確定操作なしに文章が自動送信されない。
- 他のマウスの動作を変えず、変更した設定を外せば元の操作へ戻せる。

## 今回の対象外

タブ移動、ブラウザの戻る／進む、コピー／貼り付け、クリップボード履歴、スクリーンショットなどの追加割り当ては、この基本案を試してから検討する。

## 実装

`scripts/kensington-mouse.py` がKensingtonのポインタだけを掴み、同じ入力を仮想デバイスから出し直す。
掴んだ入力をそのまま通すので、止めれば従来の操作に戻る。

| 項目 | 内容 |
| --- | --- |
| 割り当て | `platforms/ubuntu/kensington-mouse.toml`（ボタンコード、同時押しの許容時間、呼び出すコマンド） |
| 起動 | `scripts/hyprland-session.sh` がHyprlandのセッションごとに起動。ログは `~/.local/state/dotfiles/kensington-mouse.log` |
| 依存 | evdev（仮想デバイス操作用）。`platforms/ubuntu/setup-desktop.sh` が `~/.local/share/dotfiles/kensington-venv` へuvで導入する |
| テスト | `scripts/test-kensington-mouse.py`（19件） |

設計時の未決事項は次のように決めた。

- **ボタンコード**: 実機のログで確認した。下段は `BTN_LEFT`(272) と `BTN_RIGHT`(273)、左上は `BTN_MIDDLE`(274)、右上は `BTN_SIDE`(275)。型番どおりの並びではなく、上段にmiddleとsideが来ていた。
- **左右クリック**: 既存の `left_handed = true` を変えない。物理の右が主ボタン、物理の左が副ボタンになる。左上にあったmiddleクリックは、左下＋右下の同時押しに移る。
- **ワークスペース**: 既存キーバインドと同じ `hyprctl dispatch workspace e-1` / `e+1`。使用中の番号だけを移動し、端では止まる。
- **音声入力**: Shift+Space と同じ `talk-switch record toggle` を呼ぶ。右上＋左下のEscはVoxtypeのキャンセルキーとして働く。
- **同時押しの許容時間**: 200ms。下段ボタンをこれより長く押すと通常のクリック・ドラッグになる。
- **スクロール**: リングの入力をそのまま通す。

確認できたこと。

- 合成した仮想デバイスで、移動の転送、上段の単押し、3組の同時押し、停止時の後始末を確認した。
- 実機のポインタを掴んで仮想デバイスを作り、止めると元に戻ることを確認した。
- 実機で4ボタンを押し、どの位置がどのコードとして届くかをログで確認した。
- 未確認: クリックとドラッグの細かい体感。音声入力は開始・停止の呼び出しを確認済み。
