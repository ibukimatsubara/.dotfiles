Kensington 4ボタン操作

クリック、ウィンドウ移動、音声入力まで。
キーボードに手を伸ばさず、単押しと同時押しで操作するための割り当て案。

実装済み

上で選ぶ。左右で切り替える。

上の単押しはフォーカス移動。
同じ側の上下同時押しはワークスペース切り替え。

  • 下の2ボタンは、いつもの左右クリック。
  • 上の2ボタンを同時に押すと、音声入力。
  • 通常のドラッグ・ダブルクリック・スクロールは維持。

操作一覧

単押し4通り ＋ 2ボタン同時押し6通り

青いボタンを押す
「＋」はマウスの同時押し。キー名はソフトウェアが生成する入力で、キーボード操作は不要。
押す位置マウスの操作機能動作・入力
01 — 単押し
左下左クリック通常の選択。押したままボールを動かすとドラッグ。
右下右クリックコンテキストメニューを開く。
左上← 左へフォーカス同じワークスペース内で、操作対象を左のウィンドウへ。
右上右へフォーカス →同じワークスペース内で、操作対象を右のウィンドウへ。
02 — 2ボタン同時押し
左上 ＋ 左下← 前のワークスペース作業スペースを前へ切り替える。
右上 ＋ 右下次のワークスペース →作業スペースを次へ切り替える。
左上 ＋ 右上音声入力の開始／停止録音の開始と停止を切り替える。
左下 ＋ 右下中クリックアプリの中クリック動作。例：リンクを別タブで開く。
左上 ＋ 右下確定 Enterアプリによって改行・確定・送信など。必ず送信になるわけではない。
右上 ＋ 左下キャンセル Escダイアログや操作を取り消す。音声入力の破棄に使うかは要確認。

3ボタン同時押し4通りと、4ボタン同時押し1通りは予備として未割り当て。長押しや専用のダブル押しによる追加機能は、今回の案には含めない。

実装は scripts/kensington-mouse.py と platforms/ubuntu/kensington-mouse.toml。Kensingtonのポインタだけを掴んで同じ入力を出し直し、Hyprlandのセッション開始時に起動する。同時押しの許容時間は200ms。左右クリックは left_handed = true のまま（物理の右が主ボタン）。

実機のコードは下段が BTN_LEFT/BTN_RIGHT、左上が BTN_MIDDLE、右上が BTN_SIDE。左上のmiddleクリックは左下＋右下の同時押しに移る。

実機で決めること

  • 機種と入力：型番、各ボタンのコード、スクロール方式、同時押しがOSへ届くかを確認。
  • 切り替え先：「セッションの左右」はHyprlandのワークスペースと仮定。tmuxを指すなら対象を変更。
  • 前後のルール：空の番号も含めるか、使用中だけを巡回するか、端で折り返すか。
  • 音声入力：会話ではCtrl＋Space相当。リポジトリ資料はShift＋Space → Talk Switchのため、現在の実機で呼び出し先を確認。
  • 同時押し判定：押す順番・時間差の許容範囲と、通常クリック・ドラッグの応答性を両立させる。
  • 適用範囲：対象のKensingtonだけに適用し、既存設定やデバイス側の処理との二重発火を防ぐ。

使える状態の条件

  • 全10操作がマウスだけで完結。割り当て自体も実際の押しやすさを見て最終確認する。
  • 基本操作を壊さない。左右クリック、ダブルクリック、ドラッグ、スクロールを維持。
  • 同時押しは1回だけ。単押しの混入、押す・離す順番による誤発火、押しっぱなしの連発を防ぐ。
  • 未割り当てでも誤動作しない。3・4ボタン同時押しで余計な動作や押しっぱなし状態を残さない。
  • 移動先が明確。フォーカス移動とワークスペース切り替えが、決めた対象に対して動く。
  • 勝手に送信しない。音声入力の開始・停止ができ、確定操作なしに文章を送らない。
  • 元に戻せる。他のマウスを変えず、設定を外せば従来の操作に戻る。
今回含めない機能・設計上の注意
  • タブ移動、ブラウザの戻る／進む、コピー／貼り付け、クリップボード履歴、スクリーンショットは、基本案を試してから検討する。
  • Escで音声入力を破棄するかは、音声入力ツールの挙動を確認して決める。
  • この図は接続機種の外観や、同時押しが実現可能であることを保証するものではない。
  • 実機の4ボタンは、下段がBTN_LEFT/BTN_RIGHT、左上がBTN_MIDDLE、右上がBTN_SIDE。設定は対象のKensingtonだけに効き、止めれば元に戻る。
